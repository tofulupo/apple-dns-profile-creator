    Signature

    Requirements for Keychain signing

    A certificate together with its private key in your Keychain: from your organisation, from an Apple Developer account, or made yourself in Keychain Access › Certificate Assistant. Expired certificates are not listed.

    Devices show the profile as “Verified” only if they trust the certificate’s issuer. For a self-signed certificate, install it on each iPhone or iPad and turn it on under Settings › General › About › Certificate Trust Settings; on a Mac, trust it in Keychain Access.

    The first time you sign, macOS asks whether security may use the key. Choose Allow, or Always Allow to not be asked again.

    The profile is signed with a certificate from your Keychain; its private key never leaves it. Whether iOS and macOS show it as “Verified” depends on whether they trust that certificate. See the requirements above.

    The profile is not signed, so iOS and macOS label it “Not Signed” while installing and ask you to confirm. That is expected and does not affect how it works.

    Why is the profile not signed?

    Signing would require sending the profile to a server holding a private key. This tool builds the file entirely in your browser instead, so nothing leaves the device.

    An unsigned profile installs exactly the same way; iOS and macOS simply show it as “Not Signed” during installation. If you want the “Verified” label, sign the downloaded file yourself with openssl smime -sign -nodetach -outform der using a certificate your devices already trust.
